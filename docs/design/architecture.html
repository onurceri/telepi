telepi: a phone client and a safe place for Pi to work

telepi does not write an agent. It puts Pi Durable on the trusted side of your home machine, runs everything the agent does inside an OpenShell sandbox, and gives you a phone app for handing over work and answering when a boundary is about to be crossed.

Changed from the earlier diagram

  • The tool-call judges are gone as a safety layer. The pattern list and the planned model judges tried to recognise dangerous commands. The sandbox makes that unnecessary: a command can only do harm by leaving it. The pattern list remains as an opt-in.
  • No plugin system of telepi's own. A service is a preset and a credential held by OpenShell; a capability is a Durable extension.
  • Publishing runs in the sandbox. "Push branch" and "Open PR" run git push and the GitHub API call inside the sandbox, with a token the agent never sees. Both ask the first time in a project.
  • Deploy preview and the migration action are removed.
  • The plain Docker sandbox is removed. One boundary, one story.
  • Model and login come from Pi. No telepi-specific key or model list.

Not yet verified

  • Real github.com. Git with a token the supervisor fills in works against a local stand-in over plain HTTP: the sandbox saw a placeholder, the server received the token. The same against https://github.com has not been run.
  • Read versus write on one service. OpenShell has rules per HTTP method and path; telepi only uses whole-host rules so far.
  • MCP. Pi publishes a standalone MCP client, @earendil-works/pi-mcp. Wrapping it as a Durable extension is not done.
  • OAuth logins. API-key logins from Pi's files work; a subscription login that needs its token refreshed has not been tried.
  • A real phone behind Tailscale or Cloudflare Access, and notifications on it.

Kept on purpose

  • The review. A task ends with a summary, the changed files and a diff you can read before anything is published.
  • Approvals never queue offline. A late yes could land on work that has moved on.
  • Content-free notifications. The push service learns that something is waiting, not what.
  • The server is the source of truth. The phone holds a cache.
